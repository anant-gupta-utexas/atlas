## How to test T5.1 (the manual E2E gate)

T5.1 has two tracks per [`atlas-pipeline-trs-tasks.md`](atlas-pipeline-trs-tasks.md) lines 50–56:

- **T5.1 automated** — already green. `pytest -m e2e` against stubbed plugins (`tests/e2e/test_e2e_happy_path.py`).
- **T5.1 manual** — the v1.0-blocking gate. A real `atlas run` on a throwaway Flask repo with real agent plugins.

This document covers the **manual** track end-to-end. Step 0 also re-runs the automated suite as a fast smoke check.

### What "passing" means

All five TRD success criteria from `docs/2_architecture/TRD.md` lines 240–259 must hold for the same `run_id`:

1. One `runs` row, `status='success'`.
2. Exactly 7 `spans` rows in PRD order (`research → prd_draft → trd_draft → tds_gen → plan_review → code_gen → code_review`).
3. 6 `scores` rows with `scorer='user_signal'` (5 written by orchestrator, 1 written via the post-commit hook → `pending-scores.jsonl` flush).
4. `git log main` byte-identical before run start and after run close (compare on the **main** repo, not the worktree).
5. Resume protocol: kill `atlas run` mid-pipeline, run `atlas resume`, confirm it picks up at the first unchecked box in `tasks.md`.

The 7-row routing fixture passes implicitly — `Pipeline.__init__` raises `RoutingDriftError` at construction time if it doesn't.

### Preflight (verify the manual gate is even runnable)

Per `STATUS.md` line 6, T5.1 is "gated on real plugin install." Before doing anything else, confirm:

- `claude --version` resolves on PATH (the agent CLI invoked by `SubprocessStageRunner` in `src/atlas/orchestrator.py` lines 387–402: `["claude", "--slash", plugin_cmd, "--context", tasks_md, "--task", ctx.task]`).
- The 7 plugins in `src/atlas/plugin_resolver.py` lines 9–17 are reachable as slash commands of the `claude` CLI: `consult-experts`, `dev-docs-be`, `plan-reviewer`, `code-gen-agent`, `code-review`. If any plugin name differs in your install, override it via `[plugin_commands]` in `.atlas.toml`.
- `plumb` is importable (`python -c "import plumb"`) and `~/.plumb/plumb.db` is writable. `PlumbIO(real=True)` in `src/atlas/cli.py` line 41 will fail otherwise.
- `atlas` itself is on PATH (`uv sync` in repo root, then `atlas --help`).

If any are missing, **stop**: T5.1 manual cannot run yet, and `STATUS.md`'s `blocked_on` field should be updated.

### Step 1 — Build a throwaway Flask target repo

```bash
TARGET=/tmp/atlas-t51-flask
rm -rf "$TARGET"
mkdir -p "$TARGET" && cd "$TARGET"
git init -b main
git config user.email "t51@atlas.local"
git config user.name "Atlas T5.1"
# Minimal Flask skeleton — enough for the agents to "add response-cache middleware" against
cat > app.py <<'EOF'
from flask import Flask
app = Flask(__name__)

@app.route("/hello")
def hello():
    return {"ok": True}
EOF
cat > requirements.txt <<'EOF'
flask>=3.0
EOF
git add . && git commit -m "initial flask skeleton"
```

Capture the baseline for criterion 4:

```bash
git log --format='%H %s' main > /tmp/atlas-t51-mainlog-before.txt
```

### Step 2 — Install the post-commit hook + start the run

```bash
cd "$TARGET"
atlas hook install   # writes .git/hooks/post-commit per src/atlas/post_commit_hook.py:101
atlas run "add response-cache middleware to this Flask repo" --slug cache-middleware
```

`atlas run` walks the 7 stages, prompting at each gate. At gate 4 (after `tds_gen` approval) atlas creates a worktree under `.atlas/worktrees/cache-middleware-<short_run_id>/` and hands off to `code_gen`. The agent runs there; **all commits land in the worktree, never on `main`** (TRD criterion 3). The post-commit hook fires on each worktree commit and appends to `.atlas/pending-scores.jsonl`; the next orchestrator `step()` flushes that into plumb as the `gate_commit` score (see `src/atlas/orchestrator.py` lines 157–166).

Approve all gates with `a` (or whatever input the prompter accepts — see `ClickPrompter` in `src/atlas/orchestrator.py` line 439). Capture stdout/stderr to a log file: `atlas run ... 2>&1 | tee /tmp/atlas-t51-run.log`.

### Step 3 — Test resume protocol mid-run (criterion 5)

This must be done in a **second** run (or interrupt the first one before completion). Two options:

- **Option A (cleaner):** during the run above, after gate 1 or 2 approval, hit `Ctrl+C`. Then:
  ```bash
  atlas status      # shows current phase + first unchecked box
  atlas resume      # must pick up at the first unchecked stage
  ```
- **Option B:** after a clean completion, manually rewind by un-checking a box in `dev/active/cache-middleware/tasks.md` and run `atlas resume`. Less authentic; only use if Option A is infeasible.

Confirm `atlas resume` reuses the **same** `run_id` printed at the start (matches the `run_id` in `.atlas/current-run`). The unit-tested behavior in `test_e2e_resume_protocol_mid_run` (`tests/e2e/test_e2e_happy_path.py` line 188) is your reference.

### Step 4 — Verify the five success criteria against plumb

After the run closes successfully:

```bash
# Criterion 4 first — fastest to fail loudly if isolation broke.
cd "$TARGET"
git log --format='%H %s' main > /tmp/atlas-t51-mainlog-after.txt
diff /tmp/atlas-t51-mainlog-before.txt /tmp/atlas-t51-mainlog-after.txt
# MUST be empty
```

Then query plumb's SQLite DB. Pull the `run_id` from the run log or from `.atlas/current-run`:

```bash
RUN_ID=$(head -n1 "$TARGET/.atlas/current-run")
DB=~/.plumb/plumb.db

# Criterion 1: one runs row, status='success'
sqlite3 "$DB" "SELECT run_id, status FROM runs WHERE run_id='$RUN_ID';"

# Criterion 2: 7 spans in expected order
sqlite3 "$DB" "SELECT name FROM spans WHERE run_id='$RUN_ID' ORDER BY started_at;"
# Expected: research, prd_draft, trd_draft, tds_gen, plan_review, code_gen, code_review

# Criterion 3: 6 user_signal scores
sqlite3 "$DB" "SELECT metric, value_label FROM scores WHERE run_id='$RUN_ID' AND scorer='user_signal' ORDER BY ts;"
# Expected metrics: gate_research, gate_prd, gate_trd, gate_tds, gate_commit, gate_phase_complete (6 total)
```

Adjust column names to whatever plumb's actual schema is (the names above match the contract in `src/atlas/plumb_io.py`; confirm with `sqlite3 "$DB" '.schema spans'` if a query fails).

Criterion 5 was already validated in step 3.

### Step 5 — Post-run hygiene

- **Pass:** update `STATUS.md` — flip line 6 `next_gate` to "tag v1.0", flip the box at `atlas-pipeline-trs-tasks.md` line 56 to `[x]`, then proceed to T5.3 (`git tag v1.0`).
- **Fail:** capture `/tmp/atlas-t51-run.log`, the failing sqlite query output, and the diff from criterion 4. File each failed criterion as a separate issue; `STATUS.md` `blocked_on` should reference the issue list. **Do not** tag v1.0 — TRD line 261 makes any of the five a release blocker.

### Failure-mode cheatsheet

- **`RoutingDriftError` at start:** routing fixture out of sync with `STAGES`. Re-run `pytest tests/unit/test_routing_fixture_match.py`.
- **`plugin_nonzero_exit` mid-run:** plugin not installed, or `claude --slash <name>` resolution differs. Override the offending tool in `.atlas.toml` `[plugin_commands]` (`src/atlas/config.py` line 14).
- **`plugin_timeout`:** bump the per-stage timeout in `.atlas.toml` `[timeout_overrides]` (defaults: 600s plan, 1800s code_gen — D3 in `atlas-pipeline-trs-phases.md` lines 313–321).
- **5 scores instead of 6:** the post-commit hook didn't run or the flush failed. Check `$TARGET/.atlas/pending-scores.jsonl` exists and `.git/hooks/post-commit` is executable (`ls -la $TARGET/.git/hooks/post-commit`).
- **Worktree leftover:** `git worktree list` in `$TARGET`, then `git worktree remove .atlas/worktrees/cache-middleware-*` if cleanup didn't run on abort.
