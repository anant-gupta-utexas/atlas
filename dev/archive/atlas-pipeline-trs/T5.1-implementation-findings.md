## Confirmed Implementation Wins

### Plugin invocation and routing correctness

- Replaced invalid `claude --slash ...` calls with `claude -p ... --no-session-persistence`.
- Added prompt construction support for slash command and raw prompt modes in `src/atlas/plugin_resolver.py`.
- Corrected plugin command mappings, including namespaced `DEV-ESSENTIALS:*` commands.
- Updated subprocess execution to run from atlas root with `--add-dir` access for target repo/worktree.

### Pipeline control flow hardening

- Added `AutoPrompter` and `--auto-approve` support to `atlas run` and `atlas resume`.
- Added `awaiting_hook` wait behavior and repeat-attempt cap in `Pipeline.run_to_completion()`.
- Persisted and rehydrated `code_gen_span_id` via `.atlas/current-run` so hook score attribution can be recovered on resume.

### Hook and run lifecycle robustness

- Fixed `PlumbIO.close_run()` to exit the run context manager (`_run_ctx`) instead of the run handle.
- Hardened hook script generation to bake install-time interpreter and include fallback checks.
- Added warning when hook interpreter path is outside repo `.venv`.

### External plumb Phase A updates now available

- New plumb handoff guide documents child-run (`parent_run_id`) and sibling-run patterns, with same-run continuation explicitly scoped to v2.
- `RunHandle.add_score()` now accepts `rationale`.
- Plumb packaging now supports optional extras (`[cli]`, `[http]`, `[judge]`, `[all]`) with a minimal base install.
- Deferred features are now explicitly tracked in plumb docs for:
  - durable `scores.rationale`,
  - idempotent score ingestion,
  - `resume_run`,
  - `RunHandle.add_example`.

### 1) Atlas resume path aligned to plumb handoff guidance (P0) ✅

- ✅ `PlumbIO.reopen_run()` now opens a child run with `parent_run_id=<original>` per plumb handoff guide.
- ✅ `Pipeline.resume()` consumes the returned child run id and propagates it into state.

- ✅ `StateStore.create_tasks_md()` embeds original task as base64 in `<!-- task: … -->` comment.
- ✅ `StateStore.read_task_text()` restores the original task on resume, not the slug header.

### 3) Rejection examples now durable (P1) ✅

### 4) Hook idempotency guard implemented (P2) ✅

- ✅ Post-commit hook now stores `commit_sha` on each pending-scores record.
- ✅ `_already_recorded()` dedupes on `(run_id, commit_sha, metric)`.

### 6) Same-process context drift eliminated (P2) ✅

### 7) Score rationale now threaded to plumb (P2) ✅
