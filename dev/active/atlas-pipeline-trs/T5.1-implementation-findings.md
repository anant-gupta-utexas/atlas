## Open Acceptance Gaps

### 1) Atlas resume path is not yet aligned to plumb handoff guidance (P0)

- `Pipeline.resume()` calls `reopen_run(run_id)` but does not consume the returned run id.
- `PlumbIO.reopen_run()` currently opens a new run-like context (`plumb_run(task_id=run_id, kind="online")`) rather than clearly reattaching to the original active run.
- Parent/child linkage semantics from plumb handoff guidance are not explicitly enforced in atlas code.

### 2) Resume task context fidelity is still wrong (P1)

- Resume reconstructs `ctx.task` from tasks header/slug path, not from persisted original task text.
- This can degrade plugin prompt quality after resume.

### 3) Rejection examples are still stub-only durable (P1)

- In real mode, `PlumbIO.write_example()` creates an `Example` but only appends to local `self.examples`.
- No durable write call through plumb storage is performed.
- Plumb has now scoped `RunHandle.add_example` as v2, so atlas needs an interim approach.

### 4) Hook idempotency guard is still missing in atlas (P2)

- Hook appends pending score records without dedupe.
- Repeated post-commit invocations for the same commit can duplicate `gate_commit` scores.
- Plumb now tracks this as a deferred v2 capability, so atlas should enforce local dedupe meanwhile.

### 5) Span latency remains placeholder data (P2)

- `Pipeline.step()` still records `latency_ms=0.0`.

### 6) Same-process context drift can still happen (P2)

- Updated `worktree_path` context from `step()` is not propagated back to caller-owned `ctx` in `run_to_completion()`.
- This can cause `code_review` to run against repo root in same-process flow.

### 7) Atlas does not yet pass score rationale to plumb (P2)

- Plumb now supports `add_score(rationale=...)`.
- Atlas currently does not pass `GateDecision.reason` through `PlumbIO.record_user_signal()`.
